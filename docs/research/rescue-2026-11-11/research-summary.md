# Rescue research summary

Checked on 11 November 2026 against source 65e2721. This is a discussion brief, not an agreed specification.

## The problem has two parts

Rescue cannot solve this through spacing and labels alone. The classifier checks most category rules on directories, so named VM disk-file rules cannot create those rows. A broad parent match also stops child discovery. The UI then separates risk tiers before sorting by size. A protected item displays an Owner handoff label without a working management route. See coverage-and-hogs.md for source lines, test limits, and the 12-consumer matrix.

Allocated bytes measure footprint. They do not prove exclusive recoverable bytes. Shared blocks, hard links, snapshots, sparse images, and Trash all affect the result. A managed store may need an owner action instead of file deletion.

## The references do not settle one layout

CleanMyMac documents summaries and category review. DaisyDisk documents size-based exploration and a Collector. Docker exposes domain-specific storage information that a file scan cannot infer. These support different product jobs. None proves that one screen order will help Tessera users most.

The checked studies support concrete candidate review and caution with defaults. They do not supply a safe file-age threshold or a measured Tessera deletion rate. The public threads are qualitative scenarios, not a prevalence study. See reference-verification.md for the actual samples, corrections, and exact links.
