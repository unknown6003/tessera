## Cleanup fix

Owned build and fixture trees are removed by iterative postorder traversal.
The walker reopens components from a pinned root descriptor and closes each
parent as it advances. It does not retain one descriptor per depth, change the
working directory, or follow a root or child symlink. The containing path is
resolved once because macOS /tmp is a symlink. The final removal checks the
root's device and inode against the open descriptor.

Each cleanup target is attempted even if an earlier target fails. A cleanup
failure makes the job fail, preserves the original failure and step inventory,
and adds only a target name, error class and errno to the public report. No
private path is included. The report is written after cleanup, so a report
write error cannot skip removal.

The Linux suite passes 68 tool tests. A subprocess sets its descriptor limit
to 32, reproduces the old remover's EMFILE on a 280-level tree, then removes
the same tree with the new walker. It also checks a symlinked containing path
and keeps a linked outside file intact. Other controls reject a symlink root
and a parent-component root. Fault injection checks both an original failed
step and an otherwise successful job: cleanup errors must block both, without
losing the prior steps.
